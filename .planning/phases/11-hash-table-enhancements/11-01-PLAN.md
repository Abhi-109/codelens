# Phase 11 — Hash table learning enhancements + graph repair

Five workstreams, one commit each, in dependency order. Source of truth for the
lab's behaviour stays `src/datastructures/` (engine) and `src/datastructures/*.test.mjs`
plus `tools/browser-check/run.mjs` (evidence); the prose lives in
`docs/data-structures-lab.md`.

## A. Step-by-step formula breakdowns

- [x] `hashBreakdown()` returns the engine's own intermediate arithmetic
      (input, per-character codes and running sums, polynomial accumulation,
      multiplication constant and fraction, quotient/remainder) plus the formula
      and the term each step works on.
- [x] Every hash frame carries the breakdown in `detail.breakdown`; the panel in
      `StructureView.jsx` renders it and never evaluates a formula.
- [x] Back/Next, step selection, term highlight, a key field that calls the same
      engine function, an explicit raw-vs-bucket line, and reset.
- [x] Tests pin every accumulation to `rawHash()` and every index to
      `bucketIndex()`; browser checks cover the panel at desktop and 390 px.

## B. Universal hashing

- [ ] `h(k) = ((a × (k mod p) + b) mod p) mod m` as a fifth hash function, with
      deterministic `(seed, a, b, p)`, `p = 101` prime and above the capacity cap,
      a documented integer encoding, and parameter validation.
- [ ] Parameters live in state, survive ordinary operations and rehashing, and a
      seed change rehashes explicitly.
- [ ] Breakdown, journey, note and the comparison all show the same parameters.
- [ ] Tests: validity, reproducibility, multiple capacities, bounds, collisions,
      rehash preservation and determinism.

## C. Robin Hood hashing

- [ ] Linear probing with real displacement swaps (`dist(incoming) > dist(resident)`),
      not relabelled linear probing.
- [ ] Probe distance derived from home + capacity; swaps explained per step.
- [ ] Lookup with the displacement early exit; delete by backward shift (no
      tombstones) so displaced keys stay reachable.
- [ ] Update, resize, rehash, full table and wraparound covered by tests,
      including the usable non-decreasing displacement invariant per cluster.

## D. Two engine-validated prediction challenges

- [ ] `previewInsert()` runs the real insert on a clone: final slot, probes,
      swaps, whether an update happened.
- [ ] `previewResize()` runs the real insert + growth policy: grows yes/no, from,
      to, threshold comparison, duplicate-update semantics.
- [ ] "Predict the next slot" adapts its wording per strategy and distinguishes
      Robin Hood's next probe from its final placement; "Will it resize?" shows
      occupancy, load, threshold and policy.
- [ ] Tests: correct/incorrect paths, threshold boundary, duplicate update, full
      table, every strategy, determinism.

## E. Graph layout and traversal repair

- [ ] Root cause recorded: no persisted positions, one circle in node order,
      straight chords through the centre, start ring styled like a mark, no
      active traversal edge, queue/stack or order.
- [ ] Deterministic layered BFS layout with barycentre ordering, per-component
      packing, fixed spacing (so no overlap by construction) and an auto-fitted
      viewBox; direction only changes arrowheads, never positions or BFS/DFS.
- [ ] Edge routing: trimmed endpoints, curved long edges, arrowheads for directed
      graphs; no invented or suppressed edges.
- [ ] Traversal frames carry order, queue/stack and the discovering edge; the view
      draws an active edge, visited/current/start legend and the order strip.
- [ ] Editing stays consistent (invalid endpoints, duplicates, removal cleans
      edges and start, disconnected graphs); playback keeps its snapshots.
- [ ] Geometry tests: determinism, bounds, pairwise spacing, edge/node clearance,
      component separation, 12-node dense star, model order unchanged.
- [ ] Browser: DOM circle/edge geometry, active edge, queue strip, legend, both
      themes, 390 px, reduced motion.
