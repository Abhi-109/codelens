# Phase 7A: Automatic visualization planner

## Goal

A validated, explainable plan chooses one of the six real canvases from structural and recorded evidence, with a safe motion fallback and an optional AI recommendation that cannot change runtime facts.

## Dependency order

1. **A. Concepts** — `src/planner/concepts.js`; consumes the validated profile + trace + recognition. Tests: `concepts.test.mjs`.
2. **B. Capabilities** — `src/planner/renderers.js`; one entry per real `VIZ_MODES` id, no hypotheticals. Tests: `renderers.test.mjs`.
3. **C. Schema** — `src/planner/plan.js`; version 1, bounded, strict, rejects unknown renderer/concept/evidence. Tests: `plan.test.mjs`.
4. **D. Planner** — `src/planner/planner.js`; pure deterministic selection with reason codes. Tests: `planner.test.mjs` + corpus integration.
5. **E. Integration** — App computes the plan from the current run, applies it only until the user picks a canvas, shows one restrained why-line, and preserves the cursor. Browser checks.
6. **F. AI** — `src/planner/aiProvider.js` + `src/planner/aiPlanner.js`; same-origin endpoint, timeout/abort, validation, cache, stale guard. Tests: `aiProvider.test.mjs`.
7. **G. Release** — all seven gates, docs, README counts, roadmap/progress, Git.

## Task acceptance criteria

### A. Deterministic concepts
- Scalar, assignment, loop, nested loop, sequence traversal, index iteration, comparison, function, call, recursion, nested call, return, list, tuple, dict mutation, set, class, attribute, collection mutation, exception, raise, output, search-like, sort-like and graph-like candidates are detected when evidence exists.
- Invalid/empty source returns a usable `status` with diagnostics, never throws.
- Strength is `observed`, `structural` or `hypothesis`; no numeric confidence.
- Negative cases: a name alone never proves an algorithm; a list loop is not a search; a dict is not a graph algorithm.

### B. Renderer capabilities
- Every id is in `VIZ_MODES`; unknown ids are rejected; `canRender` returns explicit missing requirements.
- Capabilities state primary/secondary eligibility, events, shapes, evidence, concepts, limitations, shared cursor, reduced motion and fallback.
- Existing mode ids, labels, blurbs and saved choices are unchanged.

### C. Plan schema
- Version 1 requires schema_version, primary, fallback, provenance, concepts, emphasis and reasons; plan size, nesting and counts are bounded.
- Unknown fields, renderer ids, concepts, evidence refs and emphasis are rejected; malformed input never becomes a valid plan.
- Invalid plans fall back to motion while preserving the trace and cursor.

### D. Deterministic planner
- Identical inputs produce byte-identical plans.
- Sorting/searching recognition → Adaptive; observed recursion → Call tree; nested calls → Call tree/Combined; branch-heavy scalar → Control flow; scalar/collections → Motion; empty/syntax error → Motion with a fallback reason.
- No network, no cursor mutation, no trace mutation, no code generation.

### E. Integration
- The plan is derived from the run's profile, trace and recognition; a rerun or example switch cannot reuse a stale plan.
- Auto selection applies only while the user has not picked a canvas; manual selection remains available and is never overwritten.
- Back/Next/seek/reset/rerun, output, returns, errors, collection motion, themes, mobile and reduced motion are unchanged.

### F. AI
- Provider not configured → deterministic plan, no request.
- Timeout, abort, network, 429, invalid JSON, invalid schema, unknown renderer and oversized response all preserve the deterministic plan.
- AI concepts are hypotheses; AI cannot add evidence kinds or override observed facts.
- Cache key includes source and planner config; late responses are ignored by run identity.
- No key or secret is read from or written to the browser.

### G. Release
- `npm run test:tracer`, `test:js`, `lint`, `build`, `check:explain`, `test:pyodide`, `check:browser` run with actual results.
- README counts/structure, roadmap, animation-progress and `docs/visualization-planner.md` match the implementation.
- Work is committed and pushed only when the tree is green.
