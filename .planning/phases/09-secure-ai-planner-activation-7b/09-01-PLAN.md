# Phase 7B (GSD phase 9): Secure AI planner activation and adaptive visualization quality

## Goal

Make the Phase 7A AI boundary genuinely deployable without a secret in the browser, and prove — with an explicit corpus and a measured harness — how good automatic selection is.

## Audit findings (workstream A, complete)

- Deployment is Vercel: `vercel.json` rewrites everything to `/index.html`; there is no `api/` directory and no server runtime of any kind.
- `src/planner/{concepts,renderers,plan,planner,aiPlanner,aiProvider}.js` exist and are pure ESM. `plan.js`/`renderers.js` import only `vizMode.js` and each other, so a Node function can reuse the *same* validator instead of a second schema.
- The client request carries `untrusted_source` and `response_shape` (prompt material that belongs on the server) and omits `hasFrames`, so a server-side `canRender("scene")` check would wrongly fail.
- `aiProvider` classifies every non-2xx as `http_error`, discarding a server's classified `{error:{code}}`.
- The provider ref is created once per page, so a changed endpoint is ignored; the cache key omits the endpoint.
- No abort is issued when a run ends or the source is edited; safety today is the identity guard only.
- Planner corpus: 68 corpus programs + 54 recognition programs. Current choices are conservative and contain no false positive; the only structural gap is that a nested loop (depth ≥ 2, no collection) stays on Motion while the control-flow canvas is the honest picture of that nesting.
- `.gitignore` does not ignore `.env*`, which is a secret-leak hazard for a phase that introduces server env vars.

## Acceptance criteria

### B. Server boundary
- `POST /api/plan` accepts only the documented v1 request; every other method returns 405 and a cross-site `Origin` returns 403.
- Request body > 32 KB, source > 8 KB, > 24 concepts, > 8 renderers, unknown fields, unknown renderer ids, evidence refs or concepts are rejected without touching the provider.
- Advertised renderer capabilities must equal the real registry; the client cannot widen them.
- Missing `PLANNER_PROVIDER_KEY` returns 503 `not_configured` and no upstream call.
- Upstream timeout, non-2xx, oversized body, invalid JSON and an invalid plan each map to a classified code; no upstream body, key, stack trace or source is ever returned.
- Per-client rate limit returns 429 with `retry-after`; the limiter is bounded.

### C/D. Client and quality
- Deterministic plan is applied before any network call; AI can only replace it for the same run while unpinned.
- Cache key includes the endpoint and the full request; only validated plans are cached.
- The corpus has an explicit expected canvas per program; deterministic selection matches every expectation; no case claims sorting/searching/recursion without the corresponding evidence.
- The harness reports registered, evidence-supported, appropriate, fallback and rejection rates plus measured boundary latency, and states honestly whether AI improved anything.

### E. Lifecycle
- A new run, a source edit and unmount abort the in-flight request; a cancelled request is never an error surfaced to the user.
- Manual selection pins the canvas for the session and is never overwritten.

### F/G. Verification
- `npm run test:tracer`, `test:js`, `lint`, `build`, `check:explain`, `test:pyodide`, `check:browser`, `check:planner` all run with real results.
- Browser suite drives a mock endpoint through the real client: valid plan applied, invalid/error/timeout keep the deterministic plan, stale response ignored, manual pin preserved, cursor unchanged, two panels only, no console errors.
- Docs and GSD state match the implementation; commits are grouped by responsibility and pushed.
